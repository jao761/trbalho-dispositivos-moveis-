Você é um agente de desenvolvimento backend. Sua tarefa é criar uma **API REST completa em Python**, utilizando **FastAPI**, que consulta um **banco de dados PostgreSQL real** para simular uma API de consulta de produtos utilizada na montagem de orçamentos de clientes.

## REGRA FUNDAMENTAL DO PROJETO

O agente deve **CRIAR a estetura e tabelas os dados estão no arquivo de dados  TODAS AS TABELAS NECESSÁRIAS**.

Não assumir que:

* o banco de dados já existe;
* as tabelas já existem;
* as migrations já existem;
* o schema já foi aplicado;
* existe uma estrutura PostgreSQL pronta para ser utilizada;
* existe um banco externo para conexão.

O ambiente deve ser completamente reproduzível a partir dos arquivos gerados pelo projeto.

A estrutura SQL fornecida abaixo e o arquivo `dados-do-banco` são as **únicas bases de referência para a estrutura e os dados do projeto**.

O agente deve:

1. Criar o banco PostgreSQL por meio do `docker-compose`.
2. Criar todas as tabelas necessárias.
3. Criar todos os relacionamentos necessários.
4. Criar extensões, índices e demais objetos necessários.
5. Carregar os dados reais presentes no arquivo `dados-do-banco`.
6. Criar automaticamente qualquer tabela auxiliar necessária para atender aos requisitos da API.
7. Não depender de nenhum banco externo.
8. Não utilizar SQLite.
9. Não utilizar banco em memória.
10. Não utilizar mocks para substituir o PostgreSQL.
11. Não inventar uma estrutura de dados diferente da fornecida.
12. Caso seja necessário adaptar o arquivo `dados-do-banco` ao schema, fazer o mapeamento explicitamente e documentá-lo no README.

**O arquivo `dados-do-banco` deve ser tratado como fonte dos dados, e não como um banco ele e os dados literais da tabela pre passada mas as outrastabelas nao existem.**

A normalização deve ocorrer no PostgreSQL utilizando, por exemplo:


# 10. RANKING DA BUSCA

A busca deve ser completamente determinística.

O mesmo termo, considerando o mesmo estado do banco, deve sempre retornar o mesmo produto.

O ranking deve estar dentro da query SQL utilizando `ORDER BY CASE WHEN`.

Prioridade:

### 1. Match exato

Nome normalizado exatamente igual ao termo normalizado.

### 2. Prefixo

Nome normalizado começa com o termo.

### 3. Palavra inteira

O termo aparece como uma palavra inteira no nome.

Utilizar regex do PostgreSQL, por exemplo:

```sql
nome_normalizado ~* ('\y' || termo_normalizado || '\y')
```

Não utilizar somente:

```sql
ILIKE '%termo%'
```

para esse critério.

### 4. Fallback

Caso nenhuma das condições anteriores seja atendida:

```sql
ILIKE '%termo%'
```

como critério de menor prioridade.

### 5. Desempate

Utilizar:

```sql
ORDER BY nome ASC
```

como desempate final.

Nunca utilizar:

* ordem de INSERT;
* ordem natural do banco;
* valores aleatórios;
* `RANDOM()`.

A query deve possuir:

```sql
LIMIT 1
```

Se nenhum produto for encontrado:

```http
404 Not Found
```

com JSON padronizado:

```json
{
    "detail": "Nenhum produto encontrado para o termo informado."
}
```
